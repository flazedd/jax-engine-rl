# Reproducing the thesis results

Start with the [README quick start](README.md#quick-start-reproduce-the-saved-results).
All commands below run from the repository root with Python 3.12 and `uv sync --locked` completed.
No local thesis checkout or separately delivered archive is needed.

## Three reproduction routes

| Route | Uses | What it checks |
| --- | --- | --- |
| Saved results | Published measurements and learning curves | Statistical comparisons, tables, and plots |
| Checkpoint replay | Saved model weights and new simulated episodes | Whether the saved agents reproduce the evaluation returns |
| Full retraining | Code, configurations, and fixed seeds | Whether a new training run reproduces the research findings |

The first route is the shortest. The other two require more computation. Exact numerical
agreement across hardware is not assumed; keep the output logs and report any differences.

## File names and saved-data compatibility

Active scripts and figures use descriptive names. For example, the regime probe is
`scripts.posterior_probe`, policy substitution is `scripts.belief_swap`, and the main plotting
module is `plotting.trading_results`. The eight main configurations are in
`experiments/configs/main/`; other RSMM configurations use the `rsmm_` prefix.

Published analysis filenames and experiment identifiers retain their historical `m5r_` prefix.
The renamed scripts read and write those same data paths, so saved checkpoints and results
remain usable without migration. The current release uses seed-paired inference for the main comparisons, retaining the original
independence analysis for transparency. It also retains the corrected completed-window
learning-speed calculation. Archive checksums identify the released measurements and analyses.
Use the current commands in this guide; old Python module names have been replaced. Historical run metadata may still record the original module or config path.

## Recalculate the reported results

```bash
uv run python -m scripts.reproduce_saved_results
```

The command creates `reproduced/`, verifies the data checksums, and works on a separate copy of
the saved inputs. It fails if the output directory is already nonempty. To run it again:

```bash
uv run python -m scripts.reproduce_saved_results --output reproduced-again
```

The command performs these steps:

1. Restore the pinned original implementation-validation baseline.
2. Verify the original 18 independence-based comparisons, calculate their seed-paired counterparts,
   and publish the paired estimates as the primary analysis. Recalculate exploratory paired
   reference comparisons and preserve the six original correction families.
3. Generate the result tables and figures, including comparisons with analytical reference
   probes on each method's own observations and the full-information policy reference.
4. Check the required data, training budgets, comparison families, and numerical consistency.

`verification.json` records whether every step passed. Each stage has its own log. The strict
contract report is `results/audits/thesis_contract.json` within the output directory; a successful
check has `n_findings: 0`. It requires both probe families, evaluation, policy diagnostics,
confusion matrices, six comparison families, and all eight sets of 20 learning curves with
1,500 iterations each.

Figures are written to `figures/`, and generated LaTeX tables to `tables/`, inside the selected
output directory. The five environment-validation charts are already in the repository's
`figures/appendix/`; recomputing those charts requires the environment validation experiment
(`uv run python -m scripts.env_validation_final`), which includes training. They are not silently
presented as freshly regenerated by the saved-result command.

This route uses saved probe measurements. It does not refit classifiers or generate new policy
trajectories. The strict check without a thesis checkout checks scientific data; it does not
check prose or manually typeset thesis tables.

It also regenerates the additional descriptive analysis of trading after regime
switches from `analysis/natural_switch_evaluation.json`: the figure, interval sample counts,
and paired seed-level uncertainty. This analysis is outside the original 18 comparisons.

## Current Chapter 5 figures and tables

The quick start also verifies the decision-loss and inventory manifests, then copies their
saved inputs into `results/analysis/frozen_policy/` inside the chosen output directory.
It generates all seven main Chapter 5 figures under `figures/results/RQ1/`, including:

- `return_components.pdf`: trading gains and inventory penalties by configuration. Grey denotes
  concatenation and teal denotes hypernetworks; the trading-gains axis starts at 50.
- `decision_quality.pdf`: four mean decision-loss bars using the same matched states and weights
  within each seed. Coverage averages 70.1% (66.3–75.1% across seeds).
- `inventory_activity.pdf`: inventory exposure and accepted fills.
- `switch_overview.pdf`: reward, inventory penalties and decision loss after regime switches.

`scripts.summarize_quote_quality` recalculates the common-sample means, paired differences,
coverage and 10,000-resample intervals from the saved per-seed records. It rejects inconsistent
summaries. The saved-result route does not repeat the raw state matching or replay checkpoints.
To redo matching from cached state-action counts, follow [DECISION_LOSS.md](DECISION_LOSS.md).
Generated accuracy tables use percentages; accuracy differences use percentage points. KL
values keep their original scale.

To check against a local thesis checkout as well, use a new output directory:

```bash
uv run python -m scripts.reproduce_saved_results --output reproduced-thesis-check \
  --thesis-root /absolute/path/to/thesis
```

This checks the manually typeset result rows and compares seven regenerated supporting tables
with the thesis files. The final report requires all seven Chapter 5 figures and those tables
to exist. It records their hashes, the input manifests, the Git commit, whether the working tree
has changes, and hashes of the source files actually used. A commit hash alone does not describe
uncommitted work. The report does not claim to check thesis prose or the defense slides.

## Primary analysis and retained sensitivity results

`scripts.seed_block_sensitivity` retains its historical name: it verifies the original
independence analysis and recalculates paired bootstrap intervals and sign-flip tests.
`scripts.primary_seed_block_analysis` publishes `analysis/m5r_primary_seed_block_analysis.json`,
which the current tables and thesis use. Each primary comparison retains its original
independence estimate alongside it. All 18 corrected significance decisions agree.
The change to primary inference was made during review, not preregistered.

Matching seed identifiers, rather than array position, define pairs. Sign flips still require
symmetry of paired differences or exchangeability within pairs under the null; equal means
alone do not suffice. Exploratory full-input VariBAD probes remain outside the six correction
families. The temporal architecture-contrast plot now resamples matching seed pairs as well.

For the learned agents, same-inventory belief substitution and fixed-regime action frequencies
target the same conditional action distributions in the population limit. Sampling, weighting
and finite support differ. The two scores are complementary measurements, not independent
mechanism tests. Their saved measurements have not changed.

## Replay saved agents

Unpack the measurements and checkpoints into a new `results/` directory:

```bash
uv run python -m scripts.prepare_results --checkpoints
uv run python -m scripts.verify_checkpoint_replay
```

The replay command evaluates seed 0 for all eight conditions: 4,096 episodes in total. To check
all 160 main checkpoints instead:

```bash
uv run python -m scripts.verify_checkpoint_replay --all-seeds
```

Each checkpoint runs for 512 episodes of 128 steps with the original evaluation keys. The
command reports each difference and writes `results/analysis/checkpoint_replay_verification.json`.
It exits unsuccessfully if a difference exceeds the absolute tolerance (default `1e-10`).
A discrepancy requires inspection; changing the tolerance does not establish agreement.

`prepare_results` checks archive, individual file, and supplemental analysis input hashes before writing. Existing
identical files are accepted; differing files are never replaced. If `results/` already contains
your own runs, use a separate destination and direct the subsequent commands to it:

```bash
uv run python -m scripts.prepare_results --checkpoints --destination results-published
export THESIS_RESULTS_ROOT="$PWD/results-published"
uv run python -m scripts.verify_checkpoint_replay
```

To repeat the representation and policy measurements using the saved checkpoints:

```bash
uv run python -m scripts.posterior_probe
uv run python -m scripts.posterior_probe --classifier mlp
uv run python -m scripts.action_distributions
uv run python -m scripts.belief_swap
uv run python -m scripts.probe_confusion
uv run python -m scripts.supplemental_belief_checks --n-rollouts 500
```

These commands write new analysis outputs under `THESIS_RESULTS_ROOT` (default `results/`).
Use a separate destination to preserve another run. The supplemental check compares VariBAD's
posterior means with its full mean and standard deviation input and directly classifies regimes
using the analytical posterior on each method's own trajectories.

The published data include the analytical reference curves for the updated accuracy, KL, and
regime-change figures. To recover reference curves from older probe outputs:

```bash
uv run python -m scripts.accuracy_references
```

This replays checkpoints, refits reference classifiers, checks their aggregate scores against
the saved results, and writes `analysis/m5r_accuracy_references.json`.

## Repeat the experiments

### Additional evaluation after natural regime switches

After extracting the checkpoints, replay the four learned conditions with the original
evaluation keys (512 episodes for each of 20 trained seeds per condition):

```bash
uv run python -m scripts.natural_switch_evaluation
uv run python -m scripts.summarize_natural_switches --output-root natural-switch-report
```

The evaluator records each completed run and resumes only when its source, reference,
checkpoint, and configuration hashes match. Each run must reproduce its published mean
episode return within absolute tolerance `1e-10`. No gradients, forced switches, or environment
overrides are used. To retain a previous evaluation, pass a new `--output` path and use that
path as `--input` to the summarizer.

Age zero is the first decision under the new reward-generating regime. Windows end before
another switch or after the last trading decision; initial regime draws are not switches.
Positive inventory penalties use post-fill inventory before terminal reset. Eligible steps
are averaged within each seed, then the 20 seed means receive equal weight. Pointwise 95%
intervals use 10,000 seed bootstrap draws; hypernetwork-minus-concatenation differences retain
matching training-seed pairs. Evaluation episodes differ between conditions. These additional
comparisons are descriptive and are not adjusted for multiplicity.

Counts include distinct contributing episodes, switches, and steps for every interval. Counts
must not be summed across intervals. Later intervals select switches sufficiently early in the
episode followed by a sufficiently long uninterrupted regime, so their composition changes.
The evaluation does not isolate adaptation from inherited inventory, regime identity, or history.

### Retraining

First check the installation and print the execution plan:

```bash
uv run pytest -q
uv run python -m scripts.run_matched_programme --dry-run
```

A synthetic run checks the core pipeline and rendering without training:

```bash
uv run python -m scripts.run_matched_programme --dummy
uv run python -m scripts.verify_clean_preflight
```

Synthetic outputs are labelled and isolated in temporary directories. They are not research
results. The preflight checks that inherited publication paths remain untouched.

Start full training in separate output directories:

```bash
export THESIS_RESULTS_ROOT="$PWD/results-retrained"
export THESIS_PROJECT_FIGS="$PWD/figures-retrained"
export THESIS_FIG_ROOT="$PWD/retrained-thesis/figures"
uv run python -m scripts.run_matched_programme
```

The driver validates the configuration and environment, runs implementation checks, trains the
four reference agents and four learned variants, and performs evaluation, statistical analysis,
and presentation. Each main condition uses 20 seeds, 1,500 iterations, 512 parallel environments,
and 128 steps per episode: 98,304,000 environment steps per seed. Allow substantial compute time;
no hardware-independent runtime estimate is provided.

Progress and failures are recorded in `results-retrained/matched_programme_status.json`.
Rerun the same command with the same environment variables after an interruption. Completed
stages are reused only when their recorded inputs and outputs match. Failed prerequisites block
dependent stages. Use `--force STAGE` to repeat a named analysis stage. Historical checkpoints
are for evaluation; they are not accepted as verified resumable training caches.

The supplementary full-belief check is run separately after the programme:

```bash
uv run python -m scripts.supplemental_belief_checks --n-rollouts 500
uv run python -m scripts.plot_supplemental_belief_checks --output "$THESIS_FIG_ROOT/appendix/direct_posterior_accuracy.png"
uv run python -m scripts.exploratory_baseline_seed_pairs
```

A new training run is a replication. Inspect differences before replacing the published numbers.
Record the code commit, lock file, operating system, accelerator, driver, and library versions.
The original training hardware was not recorded in the available evidence.

## Statistical details

Learning speed is the zero-based index at the end of the first complete 25-iteration window
whose mean reaches the target. Runs that never reach the target receive 1,500, the full training budget.
Linear regime-probe comparisons are primary; MLP comparisons assess classifier sensitivity
and use a separate correction set. Chapter 5 reports the full-input linear probe scores; MLP comparisons are supporting checks.

The current thesis applies Holm correction separately to three sets of two tests: architecture
return differences, RL²–VariBAD return differences, and iterations to the return target.
The repository also retains the original 18 comparisons in six correction sets, including older
probe and policy diagnostics. The strict contract verifies these historical results as well;
they are not all primary tests in the current thesis.

The primary analysis pairs runs by training seed. Original independent estimates remain as
supporting checks. All six current return and learning-speed significance decisions agree under
both procedures. Pairing was chosen during review, rather than specified before the experiment.
Sign flips require symmetry of paired differences or interchangeable labels within pairs under
the null; matching seeds alone does not establish either assumption.

Additional control measurements, full-input probes and reference-agent comparisons report
exploratory intervals. These do not account for selecting an analysis after inspecting results.
Historical policy-substitution, response and correlation analyses remain available in the
reproduced output but are not used as main explanations in the current thesis.

## Optional: update a local thesis checkout

First run the saved-result workflow with `--thesis-root` as shown above. It creates outputs in a
separate directory and does not overwrite thesis files. Inspect regenerated outputs before
copying any changed figures or tables into the thesis. Environment-validation charts are
retained in the repository; recreating them requires the validation training runs.

Compile the thesis from its own directory:

```bash
latexmk -pdf -interaction=nonstopmode -halt-on-error main.tex
```

For checkpoint replay and rematching instructions, use [DECISION_LOSS.md](DECISION_LOSS.md) and
[INVENTORY_ACTIVITY.md](INVENTORY_ACTIVITY.md). Retraining and replay are separate from this
saved-data check.
